# ТЗ на серверную часть сайта OMEGA

Сайт сейчас готов как внешняя часть: один файл `index.html` на чистом JavaScript, без фреймворков. Все данные он хранит в браузере (`localStorage`). Нужна серверная часть: база данных, вход, расписание, уведомления.

## Общие требования

- Часовой пояс: Europe/Moscow. HTTPS. Сервер физически в России.
- Пароль ученика и инструктора: ровно 8 цифр. Хранить только хеш (argon2 или bcrypt), ограничить число попыток входа.
- Сессия: cookie с флагами HttpOnly и Secure.
- Логин человека: «Фамилия Имя», уникальный, без учёта регистра.
- Инструкторов создаёт только владелец: «Низина Елена» (первый аккаунт, пароль задаётся при установке). Новый инструктор создаётся в её профиле: логин (фамилия и имя), телефон и пароль из 8 цифр. Только владелец может создавать инструкторов, проверять это нужно на сервере.
- При первом входе инструктора сайт один раз спрашивает машину; дальше машину меняют только в профиле.
- Пароль владельца длиннее 8 цифр, 8 цифр нужно только для учеников и новых инструкторов.

## Роли

**Ученик**
- Регистрируется: фамилия и имя, телефон, пароль, сколько часов уже откатал, выбор инструктора. Заявка ждёт подтверждения инструктором.
- Только смотрит расписание своего инструктора (свободные и занятые часы без имён) и свои записи.
- Сам записаться не может.
- Может отменить свою запись до её начала, изменить адрес в записи, изменить свой телефон и основной адрес.

**Инструктор**
- Настраивает дни: «работаю» (с часами с и до), «экзамен», «выходной».
- Записывает ученика на час по логину и адресу (если адрес пустой, берётся основной адрес ученика).
- Записывает ученика на экзамен (адрес не нужен).
- Принимает или отклоняет заявки учеников и заявки на экзамен.
- Видит все предстоящие записи.
- Указывает машину при первом входе, дальше меняет её только в профиле.

## Таблицы

- `users`: id, role, login, phone, password_hash, instructor_id, status (pending, active, declined), main_address, hours_before, car.
- `day_settings`: instructor_id, date, type (work, exam, off), from_hour, to_hour.
- `bookings`: id, instructor_id, student_id, date, hour, address, address_changed, reminded.
- `exam_entries`: id, instructor_id, student_id, date, note, status (new, accepted, declined).
- `notifications`: id, user_id, text, created_at, read.
- `push_subscriptions`: id, user_id, endpoint, p256dh, auth.

Часы занятий всегда целые (по одному часу).

## API (JSON)

- `POST /api/register`, `POST /api/login`, `POST /api/logout`
- `GET /api/me`, `PATCH /api/me` (телефон, основной адрес, машина)
- `GET /api/schedule?month=YYYY-MM` (для ученика: дни, свободные и занятые часы, свои записи)
- Инструктор:
  - `PUT /api/days/:date`
  - `POST /api/bookings` (логин ученика, дата, час, адрес)
  - `DELETE /api/bookings/:id`
  - `POST /api/exams` (логин ученика, дата)
  - `PATCH /api/exams/:id`
  - `PATCH /api/students/:id` (принять или отклонить)
  - `GET /api/records` (предстоящие записи)
- Ученик: `DELETE /api/my/bookings/:id` (только до начала), `PATCH /api/my/bookings/:id` (адрес)
- Уведомления: `GET /api/notifications`, `POST /api/notifications/read`, `POST /api/push/subscribe`, `POST /api/push/unsubscribe`

## Уведомления (Web Push, ключи VAPID, библиотека `web-push`)

Отправляются сразу, при событии:

- запись или запись на экзамен: ученику;
- отмена записи инструктором: ученику;
- ответ по заявке на экзамен: ученику;
- ученик отменил занятие или изменил адрес: инструктору;
- новый ученик выбрал инструктора: инструктору.

**Напоминание за час.** Не опрашивать базу постоянно. Задача по расписанию (cron) раз в час, ровно в 00 минут по Москве: `0 * * * *` с `TZ=Europe/Moscow`. Она одним запросом по индексу (date, hour) берёт занятия, которые начнутся ровно через час и у которых `reminded = false`. Отправляет напоминание ученику (время и адрес) и инструктору (ученик, время, адрес), затем ставит `reminded = true`.

Каждое уведомление дублируется записью в `notifications` (колокольчик на сайте).

## Что нужно изменить на сайте

Сейчас сайт читает и пишет объект `st` и `localStorage` (функция `save()` и обработчики кнопок в `index.html`). После готовности API эти места заменяются запросами к серверу. Порядок: согласовать формат API, затем адаптировать сайт под него.

## Безопасность и закон

- Не хранить пароли открытым текстом. Ключи и пароли не класть в Git и в `index.html`.
- Нужны политика конфиденциальности и галочка согласия при регистрации.
- Ежедневная копия базы.
